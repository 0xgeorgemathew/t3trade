How the trading tools in T3 Trade actually work

TL;DR — The 14 trading tools are an AI agent's only API surface, exposed over MCP at POST /mcp behind a per-session bearer. None are user-facing; the UI never calls them. Twelve are thin (resolve the bound mission, delegate to a gateway/service, return). Two are load-bearing:

• trading_request_entry is the only tool that touches capital. It is split-phase — the handler dispatches a command and polls while a background reactor runs preview → guard → sign → submit → reconcile → protect.

• The watch tools register predicates that the WatchEvaluator evaluates on market data; a fired watch drives the reactor to wake the agent for another turn — closing the autonomous loop.

05The mission loop — how the agent gets woken again

Tools are not only called on-demand. A watch firing is the mechanism that resumes the agent on a schedule or market signal. This is the autonomous cycle — the same one a reviewer most often underestimates.

1
Agent turn — during a turn, the agent calls trading_register_watch with a typed predicate (price_cross, candle_close, order_update, position_update, scheduled_reassessment) bound to the current strategy version.
2
WatchEvaluator evaluates (WatchEvaluator.ts:95) — WS candle deliveries drive candle_close; a 2-second sweep drives the rest against fresh gateway reads. On match: flips active → triggered atomically (single-fire), persists a dedup-keyed inbox event.
3
Watch fires — dispatches trading.mission.watch-fired on the orchestration stream.
4
Reactor requests a run (TradingMissionReactor.ts:474) — coordinator.requestRun with retry (up to 60× / 5s, backing off behind an active run).
5
Turn coordinator gates (TradingTurnCoordinator.ts:382) — seven pre-run checks; the single decision lease (DB unique index) is the guarantee that exactly one run owns a mission at a time.
6
Provider resumed — dispatches thread.turn.start carrying a bounded TradingHarnessWakeup (cause, triggering watch, versioned snapshot). The persisted resumeCursor continues the same conversation.
7
Loop closes — agent reads trading_get_mission, sees the wakeup context + pending inbox events, and issues new tool calls.
⚠
Coverage floor — the "deaf mission" guard. When a run ends holding a position with no armed watches on both sides of the mark, ensureNotDeaf (TradingTurnCoordinator.ts:257) auto-registers a scheduled_reassessment at now + 10min. A mission can never be silently deaf with exposure open. WATCH_COVERAGE_FLOOR_MILLIS = 10 min (watch.ts:91).
