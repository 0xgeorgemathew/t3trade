The wake path

This is the end-to-end flow from a watch firing to the same session resuming. Every link is server-side; the coordinator dispatches thread.turn.start via OrchestrationEngineService and never touches ProviderService directly (§6.3 boundary). 

// A candle closes → the evaluator fires exactly once
WatchEvaluator (WS stream)
  └─ markTriggered + TradingEventInbox.persist (dedupe key)
  └─ dispatch trading.mission.watch-fired

// A reactor (or the first-run path) requests a run
TradingTurnCoordinator.requestRun
  ├─ 7 pre-run checks (§12.3)
  ├─ acquireLease (INSERT ... unique index → single lease)
  ├─ fork wake path (forkDetach — lives for the runtime)
  │   ├─ TradingWakeupComposer.compose (fresh snapshots + strategy + events)
  │   ├─ engine.dispatch(thread.turn.start)  ← the ONLY provider touch point
  │   └─ watchTurnEndAndRelease (streamDomainEvents → release lease)
  └─ return { status: "started", harnessRunId }

// The engine emits events; a reactor resumes the SAME session
OrchestrationEngine.dispatch
  └─ decider: thread.message-sent + thread.turn-start-requested
  └─ ProviderCommandReactor.processTurnStartRequested
      └─ ensureSessionForThread → REUSES existing session (no new startSession)
      └─ providerService.sendTurn (persisted resumeCursor continues conversation)

Key design decisions

  • No literal providerSessionId. Session identity IS threadId. The "same session" assertion is getStartCount() === 1.
  • turn.processing.quiesced is a no-op in production. RuntimeReceiptBusLive discards everything. The lease-release watcher uses thread.session-set on streamDomainEvents (the canonical turn-end marker).
  • The wake is a daemon fiber. requestRun returns started as soon as the lease is acquired; dispatch + watcher run detached via forkDetach.
  • No new migration. completeRun works within the existing trading_harness_runs schema (no failure_reason column; failure detail is logged).

The keystone test

The single most important proof. It establishes a session on turn 1, then dispatches a resumed turn 2 — and asserts the adapter did NOT start a second session. 

// apps/server/integration/TradingWakePath.integration.test.ts

// Turn 1: establish the session
yield* startTurn({ harness, commandId: "cmd-wake-turn-1", ... });
yield* harness.waitForReceipt(r => r.type === "checkpoint.diff.finalized" && ...);
assert.equal(harness.adapterHarness!.getStartCount(), 1);

// Turn 2: the resumed turn (what the coordinator's wake path does)
yield* harness.adapterHarness!.queueTurnResponse(THREAD_ID, turnFixture(...));
yield* startTurn({ harness, commandId: "cmd-wake-turn-2", ... });
yield* harness.waitForReceipt(r => r.checkpointTurnCount === 2);

// THE KEYSTONE: resumed turn did NOT start a new session
assert.equal(
  harness.adapterHarness!.getStartCount(),
  1,
  "resumed turn must reuse the same provider session",
);
