Live testnet evidence

The signing path was debugged against the live exchange in three probes:

  1. 422 — signature format. Packed hex string; the exchange wants {r, s, v:27|28}.
  2. 200 but wrong address — EIP-712 domain. chainId encoded as uint64; EIP-712 requires uint256 (32 bytes). Fixed → exchange recovered the correct wallet.
  3. 200 + {"status":"ok"} ✅. After both fixes, the signed noop was accepted.

Deferred / handoff to PROMPT-05

Phase 4 hands PROMPT-05 the validated signing path, the deterministic cloid, reconciled fill/position reads, and the reservation ledger that protection and position management will resize.

  • Projection join: the mission projection currently defaults the execution views to null/empty; a join against the migration-037 tables (or a 036 extension) populates them so the UI cards light up from real data.
  • Orchestration commands for trading_place_order / trading_resume_mission: the decider is exhaustive over 4 trading commands; adding the execution commands is compile-enforced (default: never) and is the natural PROMPT-05 seam to connect the harness flow to submitOrder.
  • Nonce persistence: the nonce coordinator is in-memory for the POC; a persisted recovery hint (SQLite) lands with the restart-recovery work.
  • Real order placement: the signing path is proven via noop; the first real ETH order uses the identical path once the harness flow is wired.
