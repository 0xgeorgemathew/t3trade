Gate E — live testnet evidence

A signed IOC entry of 0.01 ETH from the armed wallet was ACCEPTED and FILLED on the Hyperliquid testnet — status 200, oid 57307761690, avgPx 1833.9, fee 0.008252. The noop handshake also returns {"status":"ok"}, confirming the signing path's byte-correctness (responseType default).

Bug found & fixed at the gate: buildOrderAction omitted the required type:"order" field, so every live order action failed to deserialize with a 422. Fixed in OrderMapper (commit 5dfb4bc) — the entry then filled on the next attempt.

Close path — resolved (2026-08-02, PROMPT-04 remediation). The "signing-recovery defect" was a Hyperliquid wire field-name bug, not a signing-math issue: the order leg's client-order-id key was cloid where the canonical wire format uses c. The EIP-712 phantom-agent signature was correct throughout (verified byte-for-byte against hyperliquid-python-sdk). The wrong key changed the action hash, so our signature was self-consistent with the malformed action but the exchange recovered a different address and rejected it ("wallet does not exist"). After the one-line fix, Gate E re-run is fully green: entry accepted+filled, retry deduped via exchange-side cloid (Task 4's 0x prefix made the cloid register), close reconciled to flat, and a cancel-by-cloid action accepted live for the first time. Full evidence in the remediation report.

Highlights

  • Entry is live-accepted and idempotent. The signed IOC fills on testnet, and the execution-record / reservation unique keys mean a retry cannot duplicate it — the D1 keystone proves one record and one reservation survive a duplicate submit.
  • Loss budget and fee reserve are spec-aligned. userFees is read live, reservedRiskUsd = plannedLoss + entryFee + exitFee + slippageReserve, and the open-position risk is stop-aware (no fabricated 0 stop).
  • Exhaustion actually halts new risk. blockForExhaustion cancels mission-owned increasing orders via cancel-by-cloid on the nonce lane; guardAction blocks open/scale_in and permits close/reduce while blocked.
  • A 422 was caught at the gate, not in production. The missing type:"order" would have rejected every live order; it surfaced in Gate E and was fixed before any of this left testnet.

2 · §16.2 loss budget + Eq-4 fee reserve built

The risk reservation now reflects real fees and a real stop, not optimistic defaults.

  • Fee source live — Gateway.getTakerFeeRateBps reads userFees; reserve uses the actual taker rate.
  • Eq-4 reserve — reservedRiskUsd = plannedLoss + entryFee + exitFee + slippageReserve.
  • Stop-aware open risk — the budget reader threads the real intent stop and snapshot freshness; no fabricated 0 stop on positions that have one.
3 · §16.4 exhaustion enforcement built

When the cumulative-loss budget is exhausted, the harness can reduce risk but cannot add it.

  • blockForExhaustion cancels mission-owned increasing orders via cancel-by-cloid on the nonce lane.
  • guardAction blocks open / scale_in and permits close / reduce while blocked.
  • guardResume rejects resume while the exhaustion condition still holds.
  • D4 test pins the full permit matrix (block open, permit reduce) and the cancel-by-cloid path.
4 · Reconciled fills / positions / mark built

Reconciliation reads canonical fills, positions, and orders and gives them stable, collision-free identity.

  • mark_px derived from unrealised PnL (migration 040 column).
  • Fill identity = cloid-time-idx — fixes the prior collision where concurrent fills at the same instant collapsed.
  • websocket_reconnect trigger wired (§18.2 #2) so a dropped feed forces a full re-sync rather than a silent gap.
  • Fill-list cap aligned to 3 to bound reconciler work.

Gate E · the bug, the fix, the caveat finding

Gate E did its job: it found a defect that would have broken every live order, and it scoped exactly how far the live proof extends.

  • Defect — buildOrderAction omitted type:"order"; every order action failed to deserialize with HTTP 422.
  • Fix — added the field in OrderMapper (commit 5dfb4bc14). Entry then filled.
  • Proof scope — the entry path is live-proven. The close/reduce-only path is not: sell-action signatures recover to a wrong address on testnet.
  • Likely cause — a msgpack serialization edge for b:false in the sell action. Needs a focused investigation, not a patch in flight.
